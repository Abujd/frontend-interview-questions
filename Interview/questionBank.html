🔁 Recurring Interview Patterns
Themes that show up repeatedly across senior frontend prep material and the candidate reports checked for this guide. The "grounded in" line under each pattern names what's actually verified vs. generalized.
01

JavaScript Core Deep-Dive

Senior interviews tend to include at least one deep JavaScript round — output-based questions on closures, hoisting, and coercion, with an expectation that you can explain underlying engine behavior, not just the answer. The one fully-verified example here: LinkedIn's Senior (IC3) phone screen opened with exactly this kind of question before any UI work.

Grounded in: 1 verified report (LinkedIn). The claim that this generalizes to "every company" is this guide's inference from broader industry prep material, not a confirmed pattern across multiple sources.

02

Machine Coding: Build a Real UI Component, Live

A live 60–120 minute session building a working component. File Explorer, infinite scroll, and cursor/mouse-interaction problems are common prompts. Code quality, accessibility, and edge-case handling are evaluated, not just whether it works.

Grounded in: verified reports at LinkedIn (infinite scroll, calculator), Swiggy SDE-1 (file explorer OA, mouse-follow circle), Atlassian (file explorer, per a public question bank), and Microsoft's confirmed-but-unspecified 2-hour machine coding round. The specific "Canva: no AI tools allowed" and "Swiggy: uses CodeSandbox" details from the original draft could not be verified from the sources gathered and have been removed.

03

Frontend System Design: Design a Common UI Widget

Design an autocomplete, feed, or chat widget at the architecture level. Interviewers care about trade-offs: polling vs. WebSocket, cursor vs. offset pagination, optimistic updates, caching. The RADIO framework (Requirements → Architecture → Data Model → Interface → Optimizations) is a widely-used structure for these rounds.

Grounded in: LinkedIn's Round 2 was entirely an autocomplete design (verified). The broader claim that this is standard at Razorpay, Swiggy, Zepto, Google, and Meta is generalized from typical senior frontend loops, not individually confirmed per company here.

04

React Hooks Internals + useEffect Pitfalls

Senior React questions tend to go beyond "what is useState" into stale closures in useEffect dependency arrays, when useMemo can hurt rather than help, and useLayoutEffect vs. useEffect. React 18 features (startTransition, useDeferredValue) are increasingly common in 2025–2026 interviews as adoption of concurrent features grows.

Grounded in: general senior-React interview knowledge; not tied to a specific verified report in this guide's source set.

05

Web Performance → Core Web Vitals + Optimization

Senior performance questions increasingly ask what you've actually improved, with numbers, not just definitions. INP officially replaced FID as a Core Web Vital in March 2024 — many candidates still default to talking about FID out of habit. Code splitting, virtual scrolling, and image optimization are common follow-ups.

Grounded in: general senior-performance interview knowledge and Google's own Core Web Vitals documentation for the FID→INP transition; not tied to a specific verified company report here.

06

Product Sense + Behavioral (Hiring Manager Round)

Senior loops commonly include a hiring-manager or product-sense round assessing whether you think beyond the code: user behavior, experiment design, feature impact. Prepare 3–5 STAR stories covering impact, conflict, mentoring, and technical leadership.

Grounded in: verified at LinkedIn (app-you-use-daily + A/B testing discussion) and, separately, Swiggy SDE-1 (a "build from the ground up" hiring-manager discussion). Broader "all senior loops" framing is generalized.

07

Implement Core JS Utilities from Scratch (Polyfills)

Implementing debounce, throttle, Promise combinators, an Event Emitter, clearAllTimeouts, or bind/call/apply polyfills from memory, without libraries, is a very common senior JS-coding pattern. The expectation is production-quality code with edge cases handled.

Grounded in: clearAllTimeouts and infinite-scroll verified at LinkedIn; debounce (Flipkart), throttle (Walmart), and Event Emitter (Meta/Facebook) verified via a public frontend-interview-question repository.

08

Next.js Rendering Strategies (SSR / RSC / ISR)

Candidates who learned Next.js in the Pages Router era often struggle with App Router, Server Components, and hydration-mismatch questions. The TTFB vs. LCP trade-off between rendering strategies, and debugging hydration mismatches, are common senior-level discussion points as App Router adoption has grown through 2025–2026.

Grounded in: general senior Next.js interview knowledge; not tied to a specific verified report in this guide's source set.

  • Edge cases: empty state, error state, loading
  • No memory leaks (cleanup in useEffect)
  • Complete in under 60 minutes per component
Week 4 Frontend System Design 🔴 Highest ROI

Systems to Design

  • Autocomplete widget (most asked)
  • News Feed / Social Timeline
  • Real-time Chat (WebSocket/SSE)
  • E-commerce page with live inventory
  • Infinite scroll photo gallery

Framework per Design

  • Use RADIO: Requirements → Architecture → Data → Interface → Optimizations
  • Always discuss trade-offs (polling vs. WS, cursor vs. offset pagination)
  • Address: caching, error handling, offline, accessibility
  • Think about: skeleton screens, optimistic updates
  • Measure: which Core Web Vitals does your design affect?
